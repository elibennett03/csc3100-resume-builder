Tech Stack

Frontend: HTML, CSS (Bootstrap or Tailwind), vanilla JavaScript — single index.html SPA
Backend: Node.js + Express — RESTful API only, no MVC/SSR
Database: SQLite
AI: Any Generative AI API (Anthropic, Gemini, etc.)


Database Schema
You'll need tables for roughly:

Users — stores name, contact info, and optionally their AI API key
Jobs — each job entry with company, title, dates, and individual responsibility/detail rows
Skills — individual skills or grouped into categories
Certifications — name, issuer, date
Awards — name, description, date
Resume Profiles — a saved "version" of a resume (the selected combination of jobs/skills/certs for a specific job application)


Backend (Express API)
Standard CRUD endpoints for each data type:

GET/POST/PUT/DELETE /api/jobs
GET/POST/PUT/DELETE /api/jobs/:id/responsibilities
GET/POST/PUT/DELETE /api/skills
GET/POST/PUT/DELETE /api/certifications
GET/POST/PUT/DELETE /api/awards
GET/POST/PUT/DELETE /api/resumes — saved resume profiles

One AI endpoint:

POST /api/ai/suggest — receives a piece of text (job responsibility, skill description, etc.), sends it to the AI API, returns the suggestion back to the frontend

The AI API key should come from a .env file during development, but the app also needs to support the user supplying their own key stored in the database.

Frontend (SPA)
Single index.html that shows/hides sections. You'll have roughly these views:
Profile/Header Section

Form to enter name, email, phone, LinkedIn, location — the top of any resume

Jobs Manager

Add/edit/delete jobs
Each job has sub-entries for individual responsibilities
When a user finishes typing a responsibility, it hits the AI endpoint and shows a suggestion inline they can accept or ignore

Skills Manager

Add/edit/delete skills or skill categories
Same AI suggestion flow on input

Certifications & Awards

Simple add/edit/delete forms

Resume Builder View

User selects which jobs, which specific responsibilities per job, which skills, certs, and awards to include
This is the tailoring step — they pick what's relevant to the job they're applying for
Preview renders live as they check/uncheck items

Resume Output / Print View

A formatted resume layout driven purely by CSS
Must look good on screen and in print (@media print CSS)
Export to PDF — either using the browser's print-to-PDF or a library like html2pdf.js or jsPDF
This is the hardest part per Burchfield


AI Integration
Two touchpoints:

Inline suggestions — as the user types a job responsibility, skill description, etc., a button or blur event fires a request to your backend which calls the AI and returns a suggested rewrite
API key management — user can enter their own API key in settings, stored in SQLite, used by the backend instead of the .env key


Other Requirements to Hit

Lighthouse accessibility score 93 or above — semantic HTML, ARIA labels, proper contrast
Unique app name and favicon/icons
All libraries bundled locally — no CDNs
Library attribution popup somewhere in the UI
GitHub public repo linked in submission
AI usage documented (what prompts you used, rules files, MCP config if applicable)
Example PDF resume generated by the app included in the ZIP
